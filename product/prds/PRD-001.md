# RemNote to Obsidian Migration

## Goal

Create a CLI tool that converts a RemNote JSON export into a Markdown/Obsidian knowledge vault while preserving as much structure, metadata, references, and context as possible.

The generated vault should be usable both by humans and AI agents.

## User

Primary user:

- Daniel Kopecký

Secondary users:

- technical users migrating from RemNote to Obsidian
- users building AI-assisted knowledge systems

## Problem

RemNote stores knowledge in a complex internal JSON structure. Simple Markdown export loses hierarchy, metadata, references, relationships, and contextual information important for long-term knowledge work and AI-assisted workflows.

The user needs a portable, vendor-independent, Markdown-based knowledge system optimized for both human usage and AI-agent context loading.

## Scope

- load and validate RemNote JSON exports
- parse `rem.json` into an internal graph structure
- preserve original RemNote IDs and hierarchy
- generate Markdown files for Obsidian
- generate AI-readable metadata and manifest files
- support repeatable migration workflows
- preserve attachment references where possible

## Out of Scope

- full recreation of RemNote behavior
- bidirectional synchronization
- full spaced repetition implementation
- perfect conversion of all RemNote internal object types
- automatic semantic optimization of all notes
- becoming a full PKM platform

## Success Criteria

- a real RemNote export can be parsed successfully
- Markdown files are generated from RemNote data
- hierarchy between rems is preserved
- original RemNote IDs are preserved
- generated output can be opened in Obsidian
- AI-readable manifest files are generated
- migration can be safely re-run

## Constraints

- RemNote export format is partially undocumented
- internal RemNote object types may change over time
- unknown fields should not be silently discarded
- the first version should prioritize preservation over optimization
- output must remain Git-friendly and human-readable

## Notes

- `rem.json` is the primary source of knowledge data
- `cards.json` enriches rems through `rId -> _id`
- attachment references may exist as `%LOCAL_FILE%...` placeholders or S3 URLs
- the project should evolve incrementally through small vertical slices
